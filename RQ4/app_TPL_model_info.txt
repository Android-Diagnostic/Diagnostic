2. CONFIGURATION / INVOCATION
-----------------------------

Independence guarantee    : Every row = a brand-new session (fresh session_id, no persistence, no shared memory or
                            context). Each call received ONLY: the fixed diagnostic prompt + that row's app log +
                            that row's surrounding third-party library logs + "sample_id: <row number>".
System prompt             : "You are a helpful assistant. Follow the user's instructions exactly." (the full task
                            prompt supplied by the user was sent verbatim in the user turn, with the two log fields
                            appended under an INPUT section).
Tools                     : none enabled (pure text reasoning; no web search, no file access).
Temperature / top_p       : not user-configurable in this interface; provider defaults were used.
Extended thinking         : enabled by default in this client (355,525 thinking tokens across all successful calls).
Prompt caching            : 1-hour ephemeral caching enabled by the client (the ~720-token system prompt and the
                            per-call prompt were written to cache; because every prompt is unique there were no
                            cache reads).
Concurrency               : 10 parallel processes (first pass), 6 parallel processes (second pass).
Output validation / retry : Each model reply was parsed as a single 17-column CSV row with integer scores in {0,1,2}.
                            A reply that did not satisfy this was re-requested (fresh session each time), up to 3
                            attempts per pass. Backslash-escaped quotes (\") were normalized to CSV "" on parsing.
                            Final result: 612 / 612 rows parsed successfully; 0 rows fell back to raw output.
                            Rows by number of successful model calls needed: 1 call = 504 rows, 2 calls = 90 rows,
                            3 calls = 17 rows, 5 calls = 1 row (row 308).
sample_id                 : the 1-based input row number (the input CSV has no ID column); the merge step enforces
                            sample_id == input_row, so alignment with the input file is guaranteed.
